# 2026-07-30 — Account hardening: offline guest entry, sign-in, notification hygiene

## Summary

Fixed the four account-lifecycle bugs found in team testing, bundled in
[PR #15](https://github.com/mcdylanb/QueueMark/pull/15): "Continue as guest"
now works with zero network (lazy anonymous auth), guests can sign in to an
existing account (replace semantics), account switches clear device-global
reminders/notifications, stale notification deep links show a friendly
not-found screen instead of a blank page, and logout warns before destroying
unsynced changes. 66 unit tests green; full offline-first-run → lazy-account →
auto-sync loop verified on the emulator. Also caught a background-shell trap
that produced a phantom green build (pipeline exit code masked by `| head`).

## Log

- Root-caused the airplane-mode guest bug: `signInAnonymously()` is a
  **network call** (the server mints the uid and ID token) — "anonymous" means
  no credentials, not no server. The auth screen equated "may enter" with
  "has a Firebase user", baking a network requirement into an offline-first
  app's front door.
- **Decision — lazy anonymous auth**: `GuestSessionStore` (SharedPreferences
  flag, interface + impl for testability); "Continue as guest" sets the flag
  and navigates with zero network; the Firebase account is created
  opportunistically on tap and retried on every app start
  (`QueuemarkApplication.onCreate`). Phase 5's SyncWorker `retry()`-until-auth
  behavior then uploads accountless saves with **no new sync code** — the
  seam paid off again.
- **Decision (Dylan) — Replace semantics** for guest → existing-account
  sign-in: dialog warns, sign-in attempted FIRST (failure touches nothing),
  local wiped on success only, RemoteMirror refills. Sign-in added as a mode
  toggle inside teammates' link dialog ("Already have an account? Sign in").
- Linking with no Firebase user yet (offline-created guest) routes to
  `signUpWithEmail` instead of `linkWithCredential` (nothing to link onto).
- Cross-account notification bug fixed: reminder WorkManager jobs now tagged;
  `SyncScheduler.cancelAllReminders()` = `cancelAllWorkByTag` +
  `NotificationManager.cancelAll()`, called on logout and account switch.
- Blank-page fix: `DetailUiState.isLoaded`/`notFound` (combine's first
  emission means the DB answered); `BookmarkNotFoundState` screen with
  back action; reading timer can never prompt there.
- Logout sync-gate: dirty-row count checked first; warning dialog ("n changes
  will be lost — sign out anyway?"); navigation now fires on completed
  logout (`loggedOut` state), not on button press.
- 13 new unit tests (66 total, 0 failures): guest entry with failed anonymous
  auth, logout gate confirm/dismiss paths, sign-in replaces on success only,
  link-vs-signup routing, not-found deep links.
- Emulator verification (fresh APK, `pm clear`): airplane ON → guest entry →
  dashboard instantly, no error → bookmark saved offline (URL-fallback
  title, amber sync dot) → airplane OFF + relaunch → logcat shows lazy
  anonymous user `XsenDcwW…` created ~10 s in → SyncWorker retried →
  `Worker result SUCCESS` → "All caught up". Stale deep link
  (`--es extra_bookmark_id dead-id`) → not-found screen. Sign-in dialog mode
  verified with replace warning.

## Issues & Fixes

1. **Phantom green build** — a background `./gradlew … | grep | head` reported
   exit 0 while gradle never ran: the shell's working directory had reset and
   the pipeline's exit code came from `head`. Caught because test-result
   timestamps were a day old. Fix: run builds with output redirected to a file
   and echo `$?` explicitly; verify result freshness. (Second false-green
   lesson of this project — trust artifacts, not exit codes through pipes.)
2. **Fresh-install permission dialog intercepts UI automation** — the
   POST_NOTIFICATIONS prompt appears over the auth screen on first launch and
   ate the first scripted tap. Handle it first in any scripted run.
3. **Deep-link extras only read in `onCreate`** — delivering the test intent
   to a running instance did nothing (no `onNewIntent` handling). Test with
   `am force-stop` first. Real notifications cold-start or CLEAR_TOP anyway;
   `onNewIntent` support noted as a nice-to-have.
